## テストした内容

同梱の3,736科目から、学科・課程の分類をもとに80科目を抽出しました。大学院16科目を含みます。さらに同梱データにない模擬コースを加え、合計81のコースIDを使いました。教材名・締切・状態・成績は架空です。

- 履修数1・7・8・15・30科目、学科をまたぐ組み合わせ、大学院、同名の別科目。
- 未履修科目・前年度の科目・外部サイトのコースリンクの除外。
- 締切・状態による対象判定、同じ教材名で締切が異なる場合、重複行・重複リンク。
- 列順の変更、複数のヘッダー行、tbody外の教材行、tbody内の見出し。
- 別コースの教材へのリンク、外部リンク・ハッシュ・送信系リンク、記号やHTML文字列を含む科目名・教材名。
- 空の表に遅れて届く教材行、読み込み中表示、教材なし、19秒後の到着、部分的・全体的なタイムアウト。
- 同じ科目に複数の課題表がある場合、片方だけ未取得の場合、その状態での再取得。
- 設定OFF、空の履修一覧、時間割や課題実施状況リンクがない画面。
- 乱数seedを固定した32の組み合わせを各3回取得し、教材行・到着順を変更。

各ケースには期待する課題を定義しています。本体の解析・絞り込み関数で期待値を作らず、実際に描画された科目名・教材名・締切・順序・リンク・件数・取得状態を比較します。

## 見つかった問題と修正

修正前は3環境とも60パターン中59パターンが成功し、「同じ科目の二つの表が時間差で到着」で失敗しました。期待25件に対して10件しか表示されず、後から届く表の教材が欠落しました。

科目ごとの完了判定を、認識できたすべての課題表が読み込まれたかどうかに変更しました。科目を特定するときは、現在の表だけでなく隣の課題表に含まれる教材リンクも除外します。一部の表だけ読めた場合は、確認できた教材と前回の情報をキーで重複排除して保持し、未取得と明示します。追加した未取得状態での再取得ケースも含め、修正後は全61パターンが成功しました。

## 再実行

リポジトリー直下で実行します。

```powershell
node tests/test_deadlines.mjs
node tests/test_deadline_matrix.mjs
```

特定のケースだけ実行する場合：

```powershell
node tests/test_deadline_matrix.mjs --case multiple-tables
node tests/test_deadline_matrix.mjs --case multiple-tables-timeout
```

`tests/serve.mjs` はコマンドからも起動でき、`http://127.0.0.1:8765/tests/deadline-matrix.html` で模擬画面を確認できます。直接ブラウザーで開いた場合、取得待ちは実時間で進みます。自動実行ではブラウザーの仮想時刻で待ち時間を進めます。

機械可読な結果は `tmp/deadline-matrix/results.json`、各環境の描画HTML・ログ・結果JSONは同じフォルダーに保存します。初回の修正前結果は `baseline-results.json` に保存しました。テスト用ブラウザープロファイルは実行後に削除します。
